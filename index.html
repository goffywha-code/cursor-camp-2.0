How Real-World Multiplayer Works in Cursor Camp

Architecture breakdown & implementation pattern for live cursor synchronization

Option A: WebSockets (Socket.io)

Ideal for real-time physics & low latency. A central Node.js server maintains game state (fire power, log seating, campfire brightness) and relays 20-60 cursor updates per second to all connected clients.

Option B: Firebase Realtime DB

Serverless setup. Each player updates their custom cursor path at /campers/{userId} with position, state, marshmallow roast level, and chosen color.

Sample Socket.io Implementation

Node.js / Client 
// CLIENT: Send cursor updates on mouse motion
window.addEventListener('mousemove', (e) => {
  socket.emit('cursor_move', {
    x: e.clientX,
    y: e.clientY,
    color: myCursorColor,
    action: currentAction // 'roasting', 'sitting', 'stoking'
  });
});

// CLIENT: Smoothly render other cursors using linear interpolation (lerp)
socket.on('cursor_sync', (remoteCampers) => {
  remoteCampers.forEach(camper => {
    // lerp between last position and new server target
    camper.x += (targetX - camper.x) * 0.2;
    camper.y += (targetY - camper.y) * 0.2;
  });
});
